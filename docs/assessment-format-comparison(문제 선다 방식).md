# 진단 문항 방식 비교: 4지선다 객관식 vs 2지선다 자기평가

작성일: 2026-09-13. **2026-09-14 갱신: 팀이 2지선다 자기평가("안다/모른다") 방식으로 확정했고, 스키마·엔티티·API·데모 데이터·설계 문서까지 반영 완료했다.** 아래는 결정 당시 비교 근거로 남겨둔다.

## 배경

현재 구현·설계(`design.md`)는 분야당 9문항, 측정 영역(어휘/배경지식/독해)당 3문항씩 **4지선다 객관식(정답 채점)** 방식이다. 교수님 면담에서 "사용자가 시험처럼 느끼면 피로도가 높아져 접근성이 떨어진다"는 의견이 나왔고, 팀에서도 "1. 알고있다 / 2. 모르겠다" **2지선다 자기평가** 방식으로 바꾸는 안을 검토 중이다.

## 두 방식 요약

| | 4지선다 객관식 (현재) | 2지선다 자기평가 (검토 중) |
| --- | --- | --- |
| 질문 형태 | "다음 중 X의 의미로 가장 알맞은 것은?" + 보기 4개 | "교착 상태(deadlock)가 무엇인지 아시나요?" + 안다/모른다 |
| 채점 기준 | 정답과 선택지 일치 여부 (객관적 정오) | 사용자의 자기 판단 그 자체가 곧 데이터 (정오 개념 없음) |
| 측정하는 것 | 실제로 아는가 (능력) | 안다고 느끼는가 (자신감/인지) |

## 비교

### 1. ML 학습 신호의 신뢰도

- **객관식**: "맞았다/틀렸다"는 실제 능력에 대한 비교적 편향 적은 신호다. 사용자가 안다고 착각해도 틀리면 틀린 것으로 기록된다.
- **자기평가**: 심리학·설문 조사 분야에서 잘 알려진 **자기보고 편향(self-report bias)** 문제가 있다. 과신 편향(overconfidence bias), 더닝-크루거 효과(잘 모를수록 안다고 착각하는 경향)가 대표적이다. 즉 "안다"고 답해도 실제로는 모를 수 있어, ML이 학습하는 신호에 노이즈가 더 낄 수 있다.
- **결론**: 순수하게 "측정 정확도"만 보면 객관식이 더 신뢰도 높은 신호를 준다. 자기평가가 "더 확실하다"는 가정은 일반적으로는 반대인 경우가 많다 — 다만 아래 2번의 UX 효과로 실제 완주율/응답 품질이 달라질 수 있어 종합적으로 봐야 한다.

### 2. 사용자 경험·피로도 (교수님 의견)

- **객관식**: 보기를 다 읽고 비교·판단해야 해서 인지 부하가 크고, "시험 보는 느낌"이 든다. 특히 9문항을 연속으로 풀면 이탈(중도 포기) 가능성이 올라간다.
- **자기평가**: 즉각적으로 답할 수 있어 응답 속도가 빠르고 부담이 적다. "시험"이 아니라 "체크리스트"처럼 느껴져 접근성이 좋아질 수 있다는 게 교수님 지적의 핵심으로 보인다.
- **결론**: 이 축에서는 자기평가가 명확히 유리하다. 특히 MVP 단계에서 "일단 끝까지 완료시키는 것" 자체가 중요하다면(퍼널 이탈 방지), 이 장점이 1번의 신호 품질 단점을 상쇄할 만큼 클 수 있다.

### 3. 문제 은행 제작 난이도

- **객관식**: 그럴듯한 오답 보기 3개를 매 문항 만들어야 한다 — 난이도 조절도 어렵고 제작 시간이 오래 걸린다.
- **자기평가**: 개념 하나당 질문 하나만 있으면 된다. 문항 수를 늘리기 훨씬 쉽다 (예: 9문항이 아니라 20~30개 개념으로 확장해도 부담이 적음).

### 4. 구현 변경 범위 (자기평가로 바꿀 경우)

- `question`/`assessment_question`의 보기(options)·정답(correct_option_id) 스키마를 단순화하거나 재설계
- `assessment_answer`가 지금은 "선택한 보기 ID"를 저장하는데, 자기평가는 "안다/모른다" 같은 열거값으로 저장 방식 자체가 바뀜
- 채점 로직 삭제 (정답 비교 로직이 아예 없어짐)
- ML stub 점수 공식(`design.md`: "정답 수/발급 수")을 "자기평가 응답 비율" 기반으로 재정의해야 함 — 예: "안다" 응답 비율을 능력치로 환산
- `design.md`의 데이터 모델·ML 계약 절 전체 수정 필요

### 5. 확장 가능성

- **자기평가**는 나중에 "안다/애매함/모른다" 3단계나 "1~5점 확신도" 같은 세분화로 자연스럽게 확장 가능
- **객관식**은 오답 보기를 늘리거나(5지선다) 서술형으로 바꾸는 확장이 상대적으로 더 큰 작업

## 절충안 후보 (참고용)

팀 논의 시 극단적인 양자택일 말고 아래도 검토해볼 만하다:

1. **혼합형**: 일부 문항은 객관식, 일부는 자기평가 — 구현·설계 복잡도가 오히려 더 커져서 권장하지는 않음
2. **신뢰도 가중 자기평가**: "안다/모른다"에 더해 "확신도"까지 같이 받아서(예: 안다+확신 vs 안다+긴가민가) 자기보고 편향을 조금 보정 — UX 부담이 다시 늘어나는 트레이드오프
3. **자기평가 + 소수의 검증 문항**: 대부분은 자기평가로 가볍게 가되, 9문항 중 1~2개만 객관식으로 남겨 자기평가의 신뢰도를 간접적으로 보정 — 설계 복잡도는 크게 늘지 않으면서 순수 자기평가의 편향 문제를 약간 완화

## 팀 논의에서 결정해야 할 것

1. 신호 품질(자기평가 편향) vs 완주율/접근성(교수님 지적) 중 이 프로젝트 단계에서 뭐가 더 중요한가
2. 절충안(3단계 자기평가, 검증 문항 혼합 등)을 고려할지, 순수 이진 자기평가로 갈지
3. 결정 이후 `design.md` 데이터 모델·ML 계약·상태 전이 절을 누가/언제 수정할지
4. 문제 은행(현재 OS 분야 9문항 데모 데이터)도 새 방식에 맞게 다시 작성해야 함 — 범위 재산정 필요
