# Catalog implementation plan

**Goal:** Deliver stage 3 of the approved design: topic and book reads with opt-in demo data.
**Spec:** `docs/design.md`. Existing isolated clone and `feat/backend-prototype` are retained.
**Architecture:** Flyway owns six catalog/demo-user tables. JPA repositories load books and topic membership in bulk; DTOs expose stable pagination and feature availability, never entities. Read transactions provide consistent count/content.
**Constraints:** Java 21, Boot 4.1.1, PostgreSQL 17.11, no new dependencies, no remote push or main changes. Demo values are synthetic, not validated measurements.

## Public decisions
`GET /api/topics` returns an ID-ordered array of id/code/name/parentId.
`GET /api/books?topicId=&page=0&size=20` returns content/page/size/totalElements/totalPages, ordered by book ID. A missing topic is 404; a known topic with no directly assigned books is an empty page. Maximum size is 100.
`GET /api/books/{bookId}` returns id/title/author/description/isbn and ID-ordered topics with primary/weight/featureAvailable. Feature availability is scoped to each book/topic pair and requires active=true.
Seed is enabled with `local,demo`; default profile seeds nothing. Catalog is read-only; future write APIs must preserve DB constraints.
