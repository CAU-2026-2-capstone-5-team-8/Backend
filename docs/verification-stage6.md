# 6단계 추천·피드백 검증

검증일: 2026-09-16. 범위: 결정론적 추천 stub, 멱등성·처리 임대·실패 상태, 피드백 저장·교체, PostgreSQL 스키마.

## 로컬 검증

macOS OpenJDK 21과 Testcontainers PostgreSQL 17.11에서 다음 명령을 실행했다.

```text
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew clean build --no-daemon --console=plain
BUILD SUCCESSFUL in 33s
7 actionable tasks: 7 executed
```

JUnit XML 합계: **66개 통과, 실패 0, 오류 0, 건너뜀 0**. 실제 PostgreSQL을 사용했고 외부 ML 서버·H2·Compose DB는 사용하지 않았다. 실행 JAR도 생성됐다. 지나치게 긴 ML 모델 버전을 거부하는 테스트까지 포함한 최종 재검증 결과다.

## 동작 확인

- 최신 완료 프로필과 분야 직접 연결 도서의 활성 feature를 선택하고, 후보 수·제외 수·독자 및 특성 버전을 스냅샷한다. Top-K 성공은 201, 동일 요청의 멱등성 재생은 200이다.
- 특정 도서 모드는 topK와 무관하게 1건만 계산한다. 특성이 없는 대상은 422, 프로필 없음은 409, 잘못된 요청은 400이다.
- 같은 키의 다른 입력이나 실제 동시 요청의 처리 중 중복은 409이고, 사용자·키당 run이 하나만 남는다.
- ML 호출 실패는 내부 메시지를 숨긴 502와 영속화된 FAILED 상태로 처리하고 같은 키로 실패를 재생한다. 만료된 처리 임대의 늦은 성공 결과는 저장하지 않고 409로 정리한다.
- 완료된 추천의 피드백 최초 저장은 201, 교체는 200, 소유자가 다르면 409다. 같은 사용자·항목 피드백은 DB에 한 행만 남는다.
- stub은 네 개 적합도 평균으로 정렬하고 동점 시 도서 ID 순서를 사용한다. 모델 응답의 상관 ID·계약 버전·결과 개수·순위·후보 ID·유한한 [0,1] 점수와 이유를 검증한다.

## DB 변경

새 `V20260916053802__create_recommendation.sql`은 기존 main migration을 수정하지 않고 `recommendation_run`, `recommendation_item`, `feedback`과 상태·멱등성·점수·소유 특성의 무결성 제약을 추가한다. 기존 `book_feature`에 항목이 참조할 복합 고유 키를 추가했다.

## 제한과 다음 단계

현재 도서 다섯 권은 합성 데모이며 실제 10권 데이터 적재 경로는 없다. 추천 점수와 자기평가 프로필은 동작 확인용 규칙이지 검증된 추천 효과나 진단 정확도를 뜻하지 않는다. `ml.mode=http` Python 연동과 실제 계약 대조는 7단계, 전체 사용자 흐름 E2E는 8단계에 남아 있다. 원격 PR CI 결과는 로컬 검증과 구분해 확인한다.
